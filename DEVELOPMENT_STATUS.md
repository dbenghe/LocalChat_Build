## Launcher si optiunile Java din mediu (1.28.4)
- Problema: pe PC-ul de lucru (MBS-7774), variabila de utilizator `JAVA_TOOL_OPTIONS=-Djavax.net.ssl.trustStoreType=Windows-ROOT` a facut ca TOT HTTPS-ul din LocalChat sa cada cu `NoSuchAlgorithmException` (SunJSSE DefaultSSLContext). Cauza: runtime-ul jlink livrat (module `java.base,java.desktop,jdk.crypto.ec`) nu contine `jdk.crypto.mscapi`, deci tipul de trust store `Windows-ROOT` nu exista. Explorer pastra variabila chiar si dupa `reg delete`; ocolirea manuala era `set JAVA_TOOL_OPTIONS=` in cmd si apoi `Porneste LocalChat.bat`.
- Remediere: `packaging/Porneste LocalChat.bat` are `setlocal` si goleste `JAVA_TOOL_OPTIONS`, `_JAVA_OPTIONS`, `JDK_JAVA_OPTIONS` inainte de pornire (si pentru runtime-ul inclus, si pentru Java din sistem; efect doar in procesul launcherului, mediul utilizatorului ramane neatins). Este singurul punct de pornire: nu exista exe wrapper, relansare din aplicatie sau updater; scurtatura de pe desktop deschide acelasi .bat; procesele copil (MCP, comenzi) mostenesc mediul curatat. Daca aplicatia este pornita direct cu `java -jar`, launcherul este ocolit.
- Mesaj clar: `describe()` recunoaste esecul SSLContext implicit (`SslDiagnostics.isContextFailure`) si afiseaza un text care numeste cele trei variabile si launcherul, in loc de exceptia bruta.
- Test: `LauncherEnvTest` ruleaza launcherul real pe un runtime jlink construit ca in Build.ps1, cu variabilele setate la `-Djavax.net.ssl.trustStoreType=Windows-ROOT`. Controalele (runtime direct si launcherul 1.28.3) cad cu NoSuchAlgorithmException; launcherul nou trece, cu variabilele nesetate in procesul pornit, si pentru fiecare variabila luata separat.
- Test intermitent corectat: `SkillsCacheTest` (zip lasat in acelasi tick de timp al directorului cu scanarea anterioara) esua aleatoriu; pauza de 80 ms in test, `Skills.java` neschimbat. Daca se doreste robustete si in produs: stampila directorului ar putea include numarul de intrari.
- Constatare retea de lucru: FortiGate face inspectie SSL pe `api.xorvapi.dpdns.org` (certificatul prezentat nu este cel real), in timp ce gonkarouter si openai trec cu certificate reale. Runtime-ul livrat nu are `jdk.crypto.mscapi`, deci trust store-ul `Windows-ROOT` (care ar include CA-ul firewall-ului) nu este disponibil. In lucru separat: un proxy pe workers.dev pentru acel furnizor. Optiuni ramase daca proxy-ul nu ajunge: adaugarea modulului `jdk.crypto.mscapi` la jlink (apoi trustStoreType=Windows-ROOT ar functiona intentionat) sau importul CA-ului firewall-ului intr-un trust store propriu.

## Gandire si trunchiere (1.27.3)

Streamingul ramane implicit; deltele reasoning_content alimenteaza un indicator in bara de stare ("Modelul gandeste: ~N tokeni ...") si mentin conexiunea activa (fara HTTP 524 la ~100 s). Gandirea nu se afiseaza ca raspuns, nu se salveaza si nu se retrimite.

Control verificat pe serverul real (qwen3.6-35b-a3b): numai reasoning_effort="none" opreste gandirea (~1 s, 0 tokeni, fata de ~50-80 s si ~1,6k-2,7k tokeni); celelalte variante (chat_template_kwargs, enable_thinking, reasoning {effort}, thinking {type}, /no_think, minimal/low/high, bugete) sunt acceptate dar ignorate, deci nu sunt oferite. Meniul "Gandire" din setari rapide: Automata sau Oprita, doar API custom. 400/422 pe parametru => o reluare fara el, memorata per url|model in thinking.rejected numai dupa ce reluarea reuseste.

Rezerva adaptiva pentru gandire (~1,25 x observat, plafon 8192, sub limita API/context) se adauga numai la max_tokens; la finish_reason=length fara raspuns vizibil mesajul explica ca gandirea a consumat limita; nicio unealta dintr-un raspuns trunchiat nu ruleaza; reincercari numai 502/503/504, maximum 3; sfat dedicat la HTTP 524.

Teste: ReasoningTruncationTest in Build.ps1 (62 verificari). Amanat: mod "buget" (controlul de gandire pentru compactare/MemoryReducer a venit in 1.28.7) (niciun parametru de buget verificat). Testul de tastatura reala nu poate rula pe sesiune blocata (build cu -SkipNativeQA).

## Ce ramane de rezolvat sau de verificat

1. Disponibilitatea si latenta API: HTTP 429/503/504, intreruperile sau raspunsurile neconforme ale furnizorilor pot continua. Retry si conservarile locale reduc pierderile, nu garanteaza executia.
2. Finalizarea tehnica a unui proiect trebuie verificata pe livrabile. Un rezultat partial al agentilor, o analiza in text sau succesul unui script de test nu certifica o lista de import corecta.
3. Restructurarea completa a listelor pe faze de livrare nu are in aceasta corectie un generator local dedicat. Comparatia locala si conversia FAST nu inlocuiesc acel generator ori validarea completa a maparii articolelor.
4. Publicarea unui chat in proiectul ChatGPT al fabricii necesita un conector autorizat disponibil. Documentarea locala nu este declarata publicare in cloud.
5. Provenienta shell este conservatoare: se recunosc destinatiile de scriere literale si scripturile locale proprii invocate explicit. Numele calculate dinamic ori programele externe fara destinatii identificabile pot produce inca o notificare. Nu ascundem preventiv fisierele noi ale utilizatorului.
6. Registrul hotfolderului foloseste amprenta dimensiune/data modificarii. Nu este o analiza semantica a continutului si nu este un scanner antivirus. Ciornele si mesajele istorice nu sunt rescrise retroactiv.
7. Intelegerea vizuala depinde de model si ruta. Sunt verificate transportul si integrarea; testele sintetice nu demonstreaza interpretarea corecta a oricarei capturi reale.
8. Testele fizice de mouse/tastatura si masurarea pe desktopul utilizatorului trebuie raportate separat; nu sunt inlocuite prin teste Swing sintetice.
